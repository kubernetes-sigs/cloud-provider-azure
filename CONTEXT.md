# CVE remediation context

Terms for requested CVE fixes and how this repository performs them.

## Language

**CVE remediation request**: One strict JSON object, `cve-remediation-request/1`,
that names the findings to fix on each target branch, before any fix. It does
not record remediation results.

**CVE request template**: An optional Jinja reference for the request's JSON
layout. Requests may be generated by any method; validation checks only the
completed request's structure.

**CVE remediation target**: A branch that a request explicitly names as a
`target_branch`, together with every finding the request associates with that
branch across all its assets. Branches the request does not name are not
targets.

**CVE remediation consumer**: The part of this repository that takes a request
and performs the requested fixes on its targets.

**CVE branch remediation run**: The work of fixing one CVE remediation target,
done independently of the other targets in the same request and ending in its
own outcome.

**Unhandled CVE finding**: A well-formed finding in a request that the consumer
keeps and reports for its target but does not fix. It is not shown to be
harmless.
