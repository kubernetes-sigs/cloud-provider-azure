## Changes by Kind

### Feature

- Fix: `InvalidSourceRanges`, `InvalidAllowedIPRanges` and `ConflictConfiguration` warning events are now emitted when a Service is created or updated instead of only during delete, and are no longer emitted when the configuration is rejected and no security group change is made. Deleting a Service is no longer blocked when both `spec.loadBalancerSourceRanges` and the `service.beta.kubernetes.io/azure-allowed-ip-ranges` annotation are set.
  feat: a new `IPRangeFamilyMismatch` warning event reports IP ranges from `spec.loadBalancerSourceRanges`, `service.beta.kubernetes.io/load-balancer-source-ranges`, and `service.beta.kubernetes.io/azure-allowed-ip-ranges` whose IP family the Service does not have. ([#10893](https://github.com/kubernetes-sigs/cloud-provider-azure/pull/10893), [@Liunardy](https://github.com/Liunardy))

### Bug or Regression

- Bug fix: sends extended location when update vmss. ([#10820](https://github.com/kubernetes-sigs/cloud-provider-azure/pull/10820), [@wonderyl](https://github.com/wonderyl))
- Fix Azure failed-VM refresh operations to use PATCH so recovery is not rejected with LocationRequired. ([#10898](https://github.com/kubernetes-sigs/cloud-provider-azure/pull/10898), [@stbenjam](https://github.com/stbenjam))
- The `service.beta.kubernetes.io/azure-pip-tags` annotation no longer sets the Public IP tag keys managed by the controller (`k8s-azure-cluster-name`, `k8s-azure-service`, `k8s-azure-dns-label-service`, and their legacy names). Such keys in the annotation are now ignored, in any letter case, and a `Warning` event with reason `IgnoredPIPTagKeys` is emitted on the Service. ([#10899](https://github.com/kubernetes-sigs/cloud-provider-azure/pull/10899), [@Liunardy](https://github.com/Liunardy))
